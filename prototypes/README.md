# Prototype Kit

A starter kit for designers to rapidly build, share, and deploy interactive prototypes with [Claude Code](https://claude.ai/code). Each prototype is a standalone HTML folder deployed to GitHub Pages — no build tools, no frameworks required.

## What This Is

- A **personal prototype viewer** deployed to GitHub Pages with search, tags, and pagination
- **No styling opinions** — no bundled component library or tokens; style prototypes with your own CSS or design system
- **Pre-configured Claude Code skills** — design brainstorm/crit, UX writing review, and a visual iteration loop
- **Figma-to-prototype workflow** — give Claude a Figma link or a screenshot and it builds the UI, then iterates until it visually matches
- A **shared navigation chrome** that handles iteration/option switching and deep linking
- **Optional spatial comments** backed by GitHub Issues — click anywhere on a prototype to leave a pinned comment

## Quick Start

### 1. Create Your Repo from This Template

Push this folder to a new GitHub repo (or use **"Use this template"** if you publish it as a template). Name it something like `my-prototypes`.

### 2. Enable GitHub Pages

In your repo: **Settings** → **Pages** → Source: **"Deploy from a branch"** → Branch: **`main`**, folder: **`/ (root)`**.

### 3. Clone and Open

```bash
git clone git@github.com:<your-username>/<your-repo-name>.git
cd <your-repo-name>
claude
```

### 4. (Optional) Install the Figma Plugin

This lets Claude read your Figma designs as input for prototypes:

```bash
claude plugin install figma@claude-plugins-official
```

After installing, Claude will prompt you to authenticate with Figma the first time you use it.

### 5. Create Your First Prototype

Tell Claude what you want to explore:

```
Create a new prototype called "message-actions" that explores 3 different
hover menu designs. Make option 1 minimal, option 2 with icons, option 3
bold and colorful.
```

Claude will create the folder structure, build standalone HTML files, and set up `meta.json`. If you give it a Figma link or screenshot, it will iterate visually until the result matches (see the `/match-design` skill).

### 6. Preview Locally

```bash
./generate-manifest.sh
python3 -m http.server 8000
```

Open [http://localhost:8000](http://localhost:8000) to see the viewer.

### 7. Deploy

```bash
./generate-manifest.sh
git add -A
git commit -m "Add message-actions prototype"
git push origin main
```

Your prototype is live at `https://<your-username>.github.io/<your-repo-name>/`.

## How It Works

### The Viewer

The root `index.html` is a static viewer that lists all prototypes with search, tag filtering, and pagination. It reads `prototypes.json` (generated by `./generate-manifest.sh` and committed to the repo).

### Prototype Structure

Each prototype is a folder:

```
my-prototype/
├── index.html          # Chrome wrapper (standard template — don't modify)
├── meta.json           # Name, description, tags, options/iterations
├── thumbnail.png       # Optional (64x48) — shown in the viewer
├── option-1.html       # Standalone HTML page (loaded in iframe)
└── option-2.html
```

### The Chrome

A shared navigation header renders above every prototype with:
- Prototype name (links back to viewer)
- Iteration picker (if using iterations)
- Option pills with descriptions

URL hash enables deep linking: `#/1/2` = iteration 1, option 2.

## Styling

The kit is **unopinionated about styling** — there's no bundled component library or design tokens. Style each prototype however you like:

- A `<style>` block inside each option file (simplest for one-off explorations)
- Your own stylesheet or design-system CSS dropped into `shared/` and linked with a relative path
- Any CDN framework via a `<link>` / `<script>` tag

Each option file is a standalone HTML document loaded in an iframe, so keep it self-contained where practical.

## Claude Skills

### `/design-brainstorm`

A design crit and brainstorm partner grounded in durable product-design principles (reduce cognitive load, design for the whole context, prototype to learn, focus effort where it pays off, make bold bets). Use it to explore a design problem, get a crit on a solution, or brainstorm new directions.

### `/ux-writing`

UX writing review and recommendations — evaluates copy against content-design principles, a tone-by-context framework, and 6 litmus tests. Use it when writing or reviewing any user-facing text.

### `/match-design`

A visual iteration loop: screenshots the running prototype, compares it against a Figma link or reference screenshot, and refines until a human would perceive them as the same design. Auto-triggered when you provide a visual reference; also invokable on demand.

## Comments (Optional)

Prototypes include a spatial commenting system backed by GitHub Issues. Users click anywhere on a prototype to drop a pin and leave a comment; comments support threading, resolve/reopen, and delete.

For public GitHub, comments auto-detect the repo from your GitHub Pages URL. To enable device-flow sign-in (instead of pasting a personal access token), create an OAuth App with Device Flow enabled and set its Client ID:

```html
<script>
  window.COMMENTS_CONFIG = { clientId: 'YOUR_OAUTH_APP_CLIENT_ID' };
</script>
```

On GitHub Enterprise, set the full config (`owner`, `repo`, `apiBase`) explicitly. See the comment in `shared/comments.js`. If you don't want comments, delete `shared/comments.js` and `shared/comments.css` and remove the loader call at the end of `shared/prototype-chrome.js`.

## Tips

- **Bring your own styling** — a `<style>` block, your own CSS, or a CDN framework; the kit stays out of your way.
- **Use Figma or a screenshot as input** — Claude will build to it and run the `/match-design` loop until it matches.
- **Each option HTML file is standalone** — a full `<html>` document, loaded in an iframe.
- **Use kebab-case folder names** (e.g., `workflow-card-explorations`).
- **Add `thumbnail.png`** (64x48) for viewer card images; otherwise a placeholder is shown.
- **Run `./generate-manifest.sh` before pushing** — keeps the viewer index up to date.
- **Push to `main` to deploy** — GitHub Pages serves directly from the branch.
- **Deep links** — share specific options: `your-pages-url/my-prototype/#/0/2`.
